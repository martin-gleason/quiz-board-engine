# C20 — Survey CSV → board generator

**Owner:** agent · **Status:** built and reviewed — 60/60, `M29`–`M41` run · **Milestone:** v1.0 · **Delta:** none required

A chore, not a feature: it produces no user-visible change. It is a tool that
authors board content; the engine, the schema and the shipped site are untouched.

---

## Problem

`games/revenue-feud.json` was hand-entered from `examples/revenue_responses_17.csv`
— 17 Google Form responses, nine question columns. The transcription is
reconstructible and almost entirely mechanical, which is what makes it worth
automating: 34 of 35 cells are `count / 17 × 100`, rounded or floored.

It is also wrong in the ways hand transcription is always wrong:

- rounding is inconsistent — 25 cells rounded, 9 floored, with no rule separating them;
- one cell (`Rupert Murdock`, 7) is not derivable from the data at all. It is the
  number that makes that column sum to 100. No other column sums to 100;
- `Murdoch` became `Murdock`;
- and when the survey grows past 17 responses the whole pass is done again by hand.

The three things the transcription did that a script **cannot** derive are editorial,
and they are the reason this tool needs a second input rather than just the CSV:

| | Example |
|---|---|
| **Merge** raw answers by meaning | `"2"` + `"3"` → `"2 - 3 %"`; `"All of them"` + a 90-word rant → `"All of them!"` |
| **Drop** long-tail answers | `Investments`, `62`, `Too damn much` — but *not* `49` or `13`, also count-1 |
| **Relabel** for the board | `"0.44%"` → `".44%"`; `"Income taxes"` → `"Income Taxes (Right Answer)"` |

## Decisions taken at the gate (maintainer, this session)

1. **Editorial judgment lives in a hand-maintained map file**, not in heuristics.
   The script is pure mechanics. A raw answer the map has never seen is an **error**,
   not a silent drop and not a silent new row — the no-partial-render ethos, applied
   to tooling.
2. **Largest-remainder apportionment**, so each column's kept answers sum to exactly
   100. This replaces the manual nudge that produced `Rupert Murdock: 7`.
   **Consequence, stated because it changes shipped numbers:** the basis is the kept
   answers, so a dropped one-off redistributes its share to the survivors. Column 1
   moves from `53/24/6/6/6` (sum 95) to a set summing to 100.
3. **Regenerate the whole board file.** One source of truth. The map carries `title`,
   `theme`, `animation` and column order.
4. **Python 3, stdlib only, in `tools/`** — joins `tools/firefox-run-tests.py`.
   Tooling, so the zero-build constraint (which binds `js/`) is not engaged.

## Both artefacts are generated, and both are validated (`D46`)

The lesson `D46` was ratified for is live here: a board is not reachable without its
line in `games/games.json`, which is exactly the defect found earlier this session —
`revenue-feud.json` shipped, valid, and invisible, because the manifest never got its
line. So the manifest entry is a **first-class output of this tool**, not a sentence
telling a human to paste something.

Both outputs are validated by **the engine's own validator**, not by a Python
restatement of it: `tools/validate-board.mjs` imports `js/validator.js` and is shelled
out to. If `node` is unavailable the tool **fails** rather than skipping the gate.

**The board is validated as a `bundle`, not as a `content` document, and the distinction
is the whole point.** This was shipped wrong and adversarial review caught it.
`validateDocument` is the STRUCTURAL stage — shapes, types, limits. The checks that decide
whether a file actually loads (is this theme listed in `themes/themes.json` per spec §6.4;
does this `gameType` name a config that exists) live in `checkCrossReferences`, which runs
only from `validateBundle`. A board with `"theme": "marque"` passes every shape rule and
shows a host an error screen. The first version of this tool printed *"both outputs pass
the engine's validator"* for exactly that board and wrote it. The map is hand-edited, so a
theme typo is not an exotic input — it is the expected way in.

## Tasks

## Verification

Every assertion names a mutation and the mutation is **run** before the row is written
(`D46`). Planned as `M29`–`M33`:

| ID | Mutation | Caught by | Result |
|---|---|---|---|
| M29 | The unmapped-answer gate is removed from `tally` | the gate's own two assertions | caught, **22/24**, naming `'49 the spine'` |
| M30 | Largest remainder degrades to plain floor | the per-column sum, three ways | caught, **21/24** — columns came back 96, 97, 97, 98, 98, 99, 99, 99 |
| M31 | The manifest is keyed on the board `title` instead of `pickerKey` | the manifest assertion + the hostile-title assertion | caught, **23/25**, reproducing `M28` exactly: `games["Revenue "Feud" — \ / <script>` REFUSED |
| M32 | The validator gate is deleted from the generator | the refusal assertions, driven **through the generator** | closed — **SURVIVED at 25/25** first time; see below. After the fix, caught at **24/28** |
| M33 | The `drop` list is ignored; long tail reaches the board | the exact answer-set assertion, per column | caught, **20/25**, five columns at once |
| M33b | Apportionment basis excludes kept responses | the policing column's raw share | caught by M30 and M33 both, at 46 and 44 against an expected 47 |

**Two assertions were written wrong first, and the mutations are how that is known.**

`M31` could not fail as first written. The shipped map sets `title` and `pickerKey` to the
same string `"Revenue Feud"`, so an implementation keying the manifest on either field
produces identical output — *"a fixture that satisfies both the right and the wrong
implementation distinguishes nothing."* This is `M28`'s own failure mode, which the
register already records as having survived its first assertion for exactly this reason,
recurring in a new tool eight days later. The assertion now builds a fixture where the two
fields differ.

`M32` **survived at 25/25 green.** The assertion drove `tools/validate-board.mjs` directly
and confirmed the CLI refuses a 16-column board — which is true, and which tests the CLI
rather than the tool. The gate was deletable whole from `csv-to-board.py` with nothing
noticing. The assertion now drives the **generator**, with a map that produces an over-cap
board, and reads the exit code, the stderr, and the absence of both output files.

A third, smaller correction: the first `M31` attempt raised `NameError` and took the
harness down with it — 8 assertions collected instead of 24. Per `M21`, a mutation that
kills the report proves nothing; it was rewritten as a behavioural change.

Evidence recorded as `count` before and after, per the harness contract.

## Adversarial review

Run at the end of the build per `CLAUDE.md`. It returned **five majors and six minors**,
and re-ran the baseline itself before reporting: 28/28 on this suite, 451/451 in Firefox.
All five majors are fixed and each is now a register row with a mutation behind it.

| Finding | Fix | Mutation |
|---|---|---|
| The gate is structural-only, so the tool blesses boards the engine refuses to load | `validate-board.mjs` gains a `bundle` mode; the generator uses it | `M36` |
| A map's `filename` is used as a write path — a dry run could overwrite an arbitrary file outside the repo, before validation, with no cleanup | `safe_filename()`, the `?game=` no-traversal rule applied to the field that writes | `M38` |
| Wiping every other board from `games.json` survived 28/28 | preservation and ORDER asserted against the real manifest | `M34` |
| The earlier `games.json` fix shipped with no assertion; the browser suite stays green at 450/450 with the entry deleted | every board in `games/` asserted reachable from the manifest, in the harness that CAN list the directory | — |
| A kept answer silently lands at 0 points once the survey grows past ~290 responses | `build_column` reports zero-VALUE separately from zero-COUNT | — |

Four of the six minors are fixed too: the write phase is now atomic with rollback (`M39`),
`check_columns` reports added columns (`M35`), board header fields are asserted, and the
PII assertion — which review proved could not fail — was replaced (`M37`).

**Two findings are recorded rather than fixed, and both are honest limits:**

`M41` — the zero-count guard in `apportion` cannot be triggered. 300 000 random cases show
the guarded and unguarded versions differing in zero of them: `short` is the sum of the
fractional parts, so it is strictly smaller than the number of answers having one, and a
zero-count answer sorts last. It is defensive dead code. A mutation nothing can reach is
not evidence of a test, so the row stays open and says so.

`M33b` was **recorded wrong** and the review caught it. Its stated fixture — one "where the
readings DIFFER" between counting blanks in the denominator and not — does not exist,
because the basis is the kept answers and a blank can never enter them. Its own evidence
column admitted it was only ever seen to fail alongside `M30` and `M33`. Corrected in the
register rather than quietly deleted.

**One defect was found in the shipped tree along the way.** `games/games.json` carried
`"Revenue Feud"` **twice**, and both validators called it valid — `JSON.parse` and
`json.load` each take last-wins silently, so the duplicate is gone before a schema sees the
object. Fixed, and `M40` now asserts it against the raw text.
