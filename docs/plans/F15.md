# F15 — The editor prints a host sheet

**Owner:** agent · **Status:** BUILT — 496/496, `M52`–`M61` run · **Milestone:** v1.0
**Delta:** `D23`, **ratified 2026-09-12 by the maintainer**

---

## Problem

A host running the show needs the answers on paper. The board editor already displays every
question, answer and point value — it is the only page in the project that does — but it
prints as a web form: input boxes, buttons, a verdict panel, and whatever the browser's
dark mode decided.

The maintainer's ask, in full: *"the board editor page is what should be printed. just a
print option for that page"* — black text on a white background, with the questions, the
answers, and the point totals.

## Why this is scoped to the editor, and why that matters

The first reading of the request was a print view of the **game** board. That is a much
larger and more dangerous feature, and it is worth writing down why it was not built:

- `faceText` (`js/renderer.js:294`) returns `null` for a cell in its initial state, so an
  **unrevealed answer is not in the game's DOM at all.** `M3` exists to enforce exactly
  that. No stylesheet can print text that was never rendered.
- Anything holding a full answer key inside the game document is a surface that must never
  reach the projector.

The editor has neither problem. It already shows every answer to the one person looking at
it, and `D19` made it a separate page the game never loads. Printing it costs nothing that
the game's separation was protecting.

## The one real design decision

**The sheet is built from the editor's MODEL, not scraped from the page.**

Answers may be 2000 characters (`LIMITS.maxAnswerChars`, `js/schemas.js:123`) and they live
in `<input>` elements. An input prints **only what fits its box** — the remainder is clipped
with nothing on the paper to say so. A host would get a truncated answer and no warning,
which is worse than no sheet at all.

Printing from the model wraps properly, and it is `D46`'s rule applied where it belongs: the
printed page is a **second artefact**, and it is built from the same object the validator
judges rather than from a second reading of the DOM. The register already records what
happens when a secondary output skips the rigor applied to the primary one — `M28`, in this
same file, on the same afternoon the editor was written.

## Scope

1. A **`Print`** button in the editor, which builds the sheet from the model and calls
   `window.print()`.
2. A print-only section: the board title, then per round the **survey question**, its
   **answers in rank order**, each with its **point value**, and a **round total**.
3. An **`@media print`** block: black on white regardless of `prefers-color-scheme`, editing
   chrome hidden (open row, buttons, round and answer tools, verdict panel, manifest line,
   lede), sheet shown.
4. Feud only, because the editor is feud only (`D19`).

**Out of scope:** any change to `js/`, to the game, or to a theme. A game-side print view.
Printing a board that is not currently open in the editor.

## Open question for the maintainer, stated rather than assumed

**An invalid board.** The editor refuses to EXPORT while the board is invalid (`M25`), on
the principle that it must not hand over a file the game would reject. Printing is not
export — a host may legitimately want a draft on paper — so the plan is to **allow printing
an invalid board** and mark the sheet `DRAFT — this board does not yet validate`. Say if you
would rather printing be blocked the same way export is.

## Verification — mutations named before the code

| ID | Mutation | Must be caught by |
|---|---|---|
| M52 | The sheet is built from the DOM inputs instead of the model | a 2000-character answer reaches the sheet whole |
| M53 | The print block does not force a white background | the sheet is black-on-white with `prefers-color-scheme: dark` |
| M54 | The editing chrome is not hidden in print | no button, tool or verdict panel is in the printed sheet |
| M55 | The round total sums the wrong round | each round's total equals its own answers |
| M56 | The sheet is built once and cached, so an edit after printing prints stale | editing an answer and printing again shows the new text |
| M57 | The sheet is visible on screen, not only in print | the section is absent from the on-screen page |

`M52` is the reason this feature is not a stylesheet, so it is the row that matters most.
`M57` guards the thing that keeps the editor usable: a sheet that shows on screen turns the
editor into a document with a form stapled to it.
